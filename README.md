# NetLimiter Parser

Нативное оконное приложение для Windows, которое читает базу статистики **NetLimiter 5**
(`nlstats.db`) и показывает, кто и куда ходил в сеть: программы, время, IP-адреса, порты,
домены и объём трафика. Трафик автоматически раскладывается по готовым категориям
(заготовкам): Discord, игры, браузеры, мессенджеры, VPN, ИИ-сервисы, офис,
виртуальные машины, сеть и диагностика и т. д.

Приложение не требует Python и не изменяет базу NetLimiter: доступ только на чтение.

## Возможности

- **Соединения** — журнал подключений с временем, длительностью, программой, категорией,
  протоколом, локальным и удалённым адресом/портом, доменом и объёмом данных.
  Прокрутка виртуальная, данные читаются страницами.
- **Трафик** — агрегация таблицы `Transfers` по программе, протоколу, локальному IP,
  удалённому IP и удалённому порту. Показывает объёмы входа/исхода, число записей
  и время первой/последней активности.
- **Программы** — сводка по приложениям: соединения, объёмы, число уникальных IP,
  последняя активность.
- **Домены** — сводка по удалённым IP с именами из базы NetLimiter и определёнными
  категориями.
- **Категории** — редактор заготовок и правил классификации с проверкой, тестом,
  сохранением и сбросом к заводским настройкам.
- Поиск, фильтры по протоколу и категории, фильтр «только эта программа»,
  периоды от 15 минут до всего времени, тёмно-синяя шапка и светлая табличная тема.
- Экспорт текущего списка в CSV (UTF-8 с BOM, разделитель `;` — открывается в Excel).
- **Экспорт IP и доменов программы** — кнопка **«Домены и IP…»** на вкладке
  «Программы» или контекстное меню: полная таблица, только уникальные IP,
  только уникальные домены, а также **свой формат** для маршрутизации
  (TXT/CSV, маска IPv4 со слиянием подсетей, домены с поддоменами или без,
  удаление дубликатов).
- **Проверка обновлений** — кнопка **«Обновления»** в шапке сверяет версию
  приложения с последним стабильным релизом GitHub
  (`phenomenonRT/NetLimiterParser`), показывает номер версии, дату выпуска,
  описание изменений и открывает страницу релиза.
- Контекстные меню: подробности, копирование строки/пути/IP/домена, быстрые фильтры.

## Требования

- Windows 10 или 11, x64.
- .NET Framework 4.8 (входит в состав Windows 10/11).
- Установленный NetLimiter 5 с включённым сбором статистики.
- Файл базы обычно лежит здесь:
  `G:\Program Files\NetLimiter\nlstats.db`
  (приложение ищет его автоматически в папке статистики из
  `nl_settings.xml`, в стандартных папках установки и на фиксированных дисках).

Для сборки нужен компилятор C# из состава .NET Framework:
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Готовый файл: `NetLimiterParser.exe` в корне проекта. Скрипт использует
`app.manifest` и `app.ico`, компилирует все файлы из `src` с `/codepage:65001`.

Можно собрать вручную:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' `
  /nologo /target:winexe /platform:x64 /optimize+ /codepage:65001 `
  /out:NetLimiterParser.exe `
  /win32manifest:app.manifest /win32icon:app.ico `
  /r:System.dll /r:System.Core.dll /r:System.Drawing.dll `
  /r:System.Web.Extensions.dll /r:System.Windows.Forms.dll `
  src\*.cs
```

### Сборка и релиз на GitHub

В репозитории есть workflow `.github/workflows/build-release.yml`. Он запускается
**только вручную**, автоматических сборок по push нет:

1. Откройте на GitHub вкладку **Actions**.
2. Выберите **Build and release** → **Run workflow**.
3. Укажите тег релиза, например `v1.1.1` (допускается `1.1.1`).
4. При необходимости включите **pre-release** или **draft**.
5. Нажмите **Run workflow**.

Workflow на `windows-latest`:

- подставляет версию из тега в `src/AssemblyInfo.cs` перед сборкой (без коммита);
- собирает `NetLimiterParser.exe` через `build.ps1`;
- проверяет, что версия файла совпадает с тегом, и создаёт `SHA256SUMS.txt`;
- сохраняет exe и контрольную сумму как артефакт сборки;
- создаёт GitHub Release с указанным тегом и прикрепляет к нему
  `NetLimiterParser.exe` и `SHA256SUMS.txt`;
- при повторном запуске с тем же тегом заменяет файлы в существующем релизе.

Workflow должен находиться в ветке по умолчанию (`main`), иначе кнопка
**Run workflow** не появится. Для нового обновления указывайте тег выше уже
опубликованной версии — приложение проверяет последний стабильный релиз через
GitHub API. Черновики и pre-release в `/releases/latest` не попадают.

## Запуск

1. Запустите `NetLimiterParser.exe`.
2. Приложение само находит `nlstats.db`: сначала проверяет сохранённый путь,
   затем папку статистики из `nl_settings.xml` NetLimiter (`StatsFolderName`),
   стандартные папки установки и фиксированные диски.
3. Если база не найдена, сразу открывается окно выбора файла `nlstats.db`.
   Можно отказаться и выбрать файл позже кнопкой **«Открыть БД…»**.
4. Если база занята или находится в защищённой папке, будет создан снимок
   `%APPDATA%\NetLimiterParser\nlstats.snapshot.db` и работа продолжится с него.
5. Другой файл можно выбрать кнопкой **«Открыть БД…»**.

Если база недоступна для чтения, запустите приложение от имени администратора
(NetLimiter часто хранит статистику в `Program Files`). Подробности ошибок пишутся
в `%APPDATA%\NetLimiterParser\app.log`.

## Проверка обновлений

Кнопка **«Обновления»** в правой части шапки проверяет последний стабильный
релиз в репозитории GitHub. Приложение запрашивает GitHub API, сравнивает
версию из тега релиза (например, `v1.2.0`) с версией текущего исполняемого
файла и показывает:

- текущую версию и номер последнего релиза;
- доступна ли новая версия и когда опубликован релиз;
- описание изменений из релиза;
- кнопку **«Скачать обновление»** или **«Открыть на GitHub»**.

Проверка выполняется только по нажатию кнопки, не запускается автоматически
и не отправляет данные о базе NetLimiter. Если в репозитории ещё нет
стабильных релизов, приложение сообщает об этом. При отсутствии интернета,
таймауте или ограничении частоты запросов GitHub показывается понятное
сообщение, а страницу релизов можно открыть вручную. Для корректного
сравнения тег релиза должен начинаться с номера версии: `v1.2.0` или `1.2.0`.

Текущая версия отображается в заголовке окна и в диалоге проверки.

## Где хранятся настройки

| Файл | Назначение |
| --- | --- |
| `%APPDATA%\NetLimiterParser\settings.json` | последняя база, период, активная вкладка, размер окна |
| `%APPDATA%\NetLimiterParser\categories.json` | категории и правила классификации |
| `%APPDATA%\NetLimiterParser\nlstats.snapshot.db` | снимок базы, если оригинал занят |
| `%APPDATA%\NetLimiterParser\app.log` | журнал ошибок |

Категории можно править как в окне приложения, так и в `categories.json`
(после правки перезапустите программу). Кнопка **«Сброс»** в редакторе возвращает
19 заводских заготовок.

Файл категорий версионируется полем `version`. Если версия файла меньше текущей
версии заготовок, при запуске недостающие заводские категории и правила
добавляются один раз; существующие категории, цвета, флаги включения и ваши
собственные правила сохраняются. Удалённое вручную заводское правило может быть
восстановлено при такой миграции — после неё версия записывается в файл.
Текущая версия заготовок — 3.

## Правила классификации

В редакторе категории нажмите **«Добавить правило»**. Поддерживаются четыре типа:

| Тип | Что задаётся | Примеры |
| --- | --- | --- |
| **Процесс** | имя или путь программы; `*` и `?` — подстановочные знаки | `discord.exe`, `*steam*`, `C:\Games\*\game.exe` |
| **Домен** | домен или его часть; `*` и `?` поддерживаются | `discord.com`, `*.googlevideo.com`, `github` |
| **IP / подсеть** | адрес IPv4/IPv6 или подсеть CIDR | `162.159.192.0/24`, `8.8.8.8`, `2001:db8::/32` |
| **Порт** | номер, диапазон или протокол + диапазон | `443`, `27015-27050`, `udp:27015-27050` |

Приоритет совпадений (больше — важнее):

1. Точный путь процесса — 120, точное имя процесса — 110.
2. Процесс с подстановочными знаками — 90–110.
3. Домен — 80–95, IP/подсеть — 72–82, порт — 60.

Поэтому правило программы обычно перекрывает доменные и IP-правила. Если для
соединения не нашлось ни одного правила, оно попадает в **«Другое»**.

Кнопка **«Тест…»** позволяет ввести программу, домен, IP, порт и протокол и увидеть,
какая категория и какое правило сработают. Тест использует **сохранённые** правила:
после правок нажмите **«Сохранить»**.

## Экспорт IP и доменов программы

1. Откройте вкладку **«Программы»** и выберите нужную строку.
2. Нажмите **«Домены и IP…»** справа над таблицей или щёлкните строку правой
   кнопкой мыши и выберите **«Экспорт IP и доменов»**.
3. Выберите режим:
   - **Полная таблица** — IP, домен, категория, протоколы, число соединений,
     вход, исход, всего и последняя активность;
   - **Только IP-адреса** — уникальные IPv4/IPv6 по одному в строке;
   - **Только домены** — уникальные доменные имена по одному в строке;
   - **Свой формат…** — настраиваемый список для маршрутизации.

Экспорт учитывает **текущий период** и **фильтр протокола**, но не зависит от
поиска и фильтра категории: выгружаются все адреса и домены выбранной программы.
Если программа отфильтрована чипом «Программа», кнопка также работает без выбора
строки. Домены берутся из кэша обратных имён NetLimiter; для IP без известного
имени колонка «Домен» будет пустой. Стандартные CSV-файлы записываются в UTF-8
с BOM и разделителем `;`.

### Свой формат для маршрутизации

Пункт **«Свой формат (TXT/CSV, маска IP, поддомены)…»** открывает окно
с настройками списка:

| Настройка | Значение |
| --- | --- |
| **Что выгрузить** | IP и домены в один столбец, только IP-адреса или только домены |
| **Формат файла** | TXT — по одному значению в строке без заголовка; CSV — один столбец с заголовком `Значение` |
| **Маска IPv4** | Группирует IPv4 в подсети: `162.159.128.5` → `162.159.128.0/24`. IPv6 всегда выводится точным адресом |
| **Сливать соседние подсети** | Объединяет смежные и вложенные CIDR в минимальный набор: `10.0.0.0/24` + `10.0.1.0/24` → `10.0.0.0/23`; четыре выровненные `/24` → `/22` |
| **Оставлять поддомены** | Включено — полные имена (`cdn.discordapp.com`); выключено — основной домен (`discordapp.com`) |
| **Удалять дубликаты** | Убирает повторяющиеся значения. При слиянии подсетей результат всегда уникален |

Значения выводятся в порядке: IPv4-адреса и CIDR (по возрастанию), затем IPv6,
затем домены по алфавиту. TXT пишется в UTF-8 с BOM, без заголовка; CSV —
с заголовком `Значение`. Пустые домены пропускаются.

Маска задаёт начальную гранулярность. Слияние может сделать блок шире
выбранной маски — это уменьшает список маршрутов, но захватывает больше
адресов. Перед добавлением в маршрутизатор проверьте получившиеся CIDR.

Основной домен без поддоменов определяется эвристически по списку частых
двухуровневых зон (`co.uk`, `com.au`, `com.br` и т. п.). Для редких зон
проверьте результат перед использованием в маршрутизации.

#### Примеры для систем маршрутизации

**sing-box.** Фрагмент правила маршрута:

```json
{
  "domain_suffix": ["discord.com", "discordapp.com", "discordapp.net"],
  "ip_cidr": ["162.159.128.0/23", "162.159.130.0/24"]
}
```

Для доменов лучше выгружать вариант **без поддоменов** и использовать
`domain_suffix` — тогда правило накроет все поддомены. Если нужны точные имена,
используйте ключ `domain`.

**HydraRoute Neo.** Домены добавляются в `domain.conf` строкой через запятую
с политикой или интерфейсом:

```
discord.com,discordapp.com,discordapp.net/HydraRoute
```

CIDR добавляются в `ip.list` блоком:

```
/HydraRoute
162.159.128.0/23
162.159.130.0/24
```

В веб-интерфейсе HRweb домены и CIDR можно вставить в поле правил — по одному
значению в строке.

**MagiTrickle.** Домены добавляются как правила Namespace (домен со всеми
поддоменами) или Domain (точное имя), а CIDR — как IPv4/IPv6 subnet. Список из
TXT удобно вставлять в поле правила по одному значению в строке.

## Периоды и производительность

- По умолчанию открывается последние 24 часа относительно последней записи в базе.
- «Всё время» может агрегировать миллионы соединений: сводки по программам и IP
  считаются дольше (единицы–десятки секунд), прогресс виден в оверлее, операцию
  можно отменить.
- Поиск и фильтр по категории в «Соединениях» сканируют до 100 тысяч последних
  записей за один проход. Если совпадений больше или нужен более старый участок,
  нажмите **«Загрузить ещё»**.
- Время в интерфейсе показывается в локальном часовом поясе; в базе NetLimiter
  хранит время в UTC.

## Горячие клавиши и мелочи

- **Enter** в поле поиска — применить фильтр сразу (иначе применяется с задержкой).
- **Двойной щелчок** по строке — окно подробностей.
- **Правый щелчок** — копирование и быстрые фильтры.
- Крестик в поле поиска очищает запрос.
- Кнопка **«Сброс»** снимает все фильтры, но не меняет период.
- **«Обновить»** перечитывает статистику базы и текущую вкладку.

## Диагностика

- **«Не удалось открыть базу данных»** — проверьте путь, права на файл и что
  NetLimiter не удерживает базу монопольно; приложение попробует снимок.
  Если база не найдена автоматически, выберите `nlstats.db` в открывшемся окне
  или кнопкой **«Открыть БД…»**.
- **Пустые списки** — выбран период без данных или слишком узкий фильтр; нажмите
  «Сброс» и переключите период.
- **Медленно на «Всё время»** — это нормально для базы в несколько гигабайт;
  используйте меньший период или дождитесь завершения (операцию можно отменить).
- **Не удалось проверить обновления** — проверьте подключение к интернету,
  прокси или откройте https://github.com/phenomenonRT/NetLimiterParser/releases
  вручную. GitHub может ограничивать частоту анонимных запросов.
- **Ошибка `winsqlite3.dll`** — библиотека входит в Windows 10/11; на урезанных
  сборках Windows её может не быть.
- Все ошибки дублируются в `%APPDATA%\NetLimiterParser\app.log`.
